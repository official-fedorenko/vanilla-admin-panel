# Vanilla Admin Panel + Учёт компании (Node.js + SQLite)

> 🏢 **Коммерческая сборка (UAB Diamantas)** — на основе опенсорсной админки развёрнута внутренняя система учёта компании: сотрудники, электроинструмент, заявления, QR-карточки инструмента и поддержка. Основной функционал стабилен; перед использованием в production внимательно относитесь к безопасности и делайте бэкапы.

Лёгкая **self-hosted** система учёта + CMS + личный кабинет, написанная **на чистом Node.js без фреймворков** и **SQLite**.

Фронтенд — чистый HTML + CSS + Vanilla JS с тёмным дизайном (glassmorphism, градиенты, плавные анимации). Никакой сборки, бандлеров и SPA-фреймворков.

**Особенности проекта:**
- Бэкенд — нативный модуль `http` без Express/Koa/Fastify
- Немного рантайм-зависимостей: `sqlite3`, `qrcode`, `sanitize-html`, `dotenv`
- Сессии переживают перезапуск сервера (хранятся в БД)
- Усиленная защита регистрации от ботов «из коробки» + опциональная 2FA (TOTP)
- Подходит как основа для внутренней системы небольшой компании

## ✨ Возможности

- **Публичный сайт** (блог)
  - Динамическая загрузка статей и настроек
  - Адаптивный дизайн, гостевое меню входа/регистрации в модалке на мобильных

- **Личный кабинет** (`/cabinet.html`)
  - Редактирование профиля (email + смена пароля), выбор/загрузка аватарки
  - Двухфакторная аутентификация (TOTP)
  - «Моя карточка сотрудника» и «Мой инструмент» (для сотрудников)
  - **Заявления**: подача через двухшаговую модалку (сначала тип, затем форма) — добавить/заказать инструмент, отпуск, увольнение
  - **Учёт рабочего времени**: внесение записей (дата + часы + заметка), список своих записей и итог
  - Чат с администрацией; все карточки сворачиваются на мобильных

- **Админ-панель** (`/admin/`)
  - CRUD статей (Quill WYSIWYG редактор + предпросмотр)
  - **Медиатека** с drag & drop загрузкой, разделами (инструменты/аватары/поддержка) и авто-сжатием изображений; стандартные иконки категорий и стандартные аватары — в модалках
  - **Учёт сотрудников** (CRUD, статусы: работает / в отпуске / неактивен / уволен)
  - **Учёт инструмента**: инвентарь, выдача/возврат/передача, история закреплений, статистика, авто-инвентарный номер, **галерея фото** (первое фото → аватар, аватар выбирается только из фото инструмента), **QR-код** и публичная карточка
  - **Заявления**: одобрение/отклонение; одобрение «добавить инструмент» создаёт запись в инвентаре
  - **Отпуска**: сводка «кто и когда в отпуске» — мини-календарь (таймлайн с линией «сегодня») и список с датами, кол-вом дней и метками «сейчас в отпуске / предстоит / завершён»; показывает одобренные и ожидающие заявки, фильтр по периоду
  - **Учёт рабочего времени**: сводка часов по каждому пользователю + просмотр записей выбранного сотрудника
  - **Поддержка**: список всех пользователей с поиском, счётчик непрочитанных у ников и общий бейдж в меню, переписка открывается в модалке; админ может писать любому первым
  - Редактор системных настроек (включая видимость полей публичной карточки инструмента)
  - Управление пользователями (только Superadmin), логи действий, бэкап БД

- **Публичная карточка инструмента по QR** (`/tool.html?id=…`)
  - Открывается любым человеком без авторизации — для идентификации инструмента
  - Что показывать (фото, категория, бренд, модель, серийный/инвентарный №, статус, дата покупки, заметки) настраивается **глобально** в разделе «Настройки»
  - Карточку целиком можно выключить

- **Безопасность и защита от ботов**
  - PBKDF2 хэширование паролей (120 000 итераций + обратная совместимость)
  - HttpOnly + SameSite=Strict куки, серверные сессии в БД
  - Двухфакторная аутентификация (TOTP) с резервными кодами
  - **Усиленная защита регистрации**: математическая капча, honeypot-поля, минимальное время на странице, серверная верификация
  - Rate limiting на логин/регистрацию (в памяти)

- **Технические особенности**
  - Автоматический сид дефолтных аккаунтов, настроек и демо-данных
  - Роли: `Superadmin` / `Admin` / `User`; не-админов в `/admin` не пускаем (редирект в кабинет)
  - Загрузка файлов через JSON + base64 с авто-сжатием изображений в браузере
  - Мобильная адаптивность (сворачиваемые карточки, меню профиля по тапу, сетка меню)

## 🔑 Аккаунты по умолчанию

При первом запуске (когда `db.sqlite` отсутствует) автоматически создаются:

| Логин        | Пароль     | Роль        | Назначение                     |
|--------------|------------|-------------|--------------------------------|
| `superadmin` | `1234qwer` | Superadmin  | Полный доступ                  |
| `admin`      | `1234qwer` | Admin       | Контент + поддержка + учёт     |
| `user`       | `1234qwer` | User        | Обычный пользователь + кабинет |

> **⚠️ Обязательно** сразу смените пароли после первого входа. Дефолтные аккаунты существуют только для удобства первого запуска.

## 🚀 Быстрый старт

```bash
# 1. Клонирование и установка
git clone <your-repo>
cd vanilla-admin-panel
npm install

# 2. (Опционально) переменные окружения
cp .env.example .env
# Отредактируйте .env при необходимости (например, PORT=4000)

# 3. Запуск
npm start                 # production-режим
npm run dev               # с автоперезапуском (node --watch)
```

Откройте в браузере: **http://localhost:3080** (или порт из `.env`).

Требуется **Node.js 18.11+ / 20+** (используется нативный `node --watch` и `node:test`).

### Особенности запуска на Windows (PowerShell)

Если `npm run dev` не работает — используйте `cmd`, либо:
```powershell
Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser
# или напрямую:
node --watch server.js
```

## 🔐 Безопасность

- **Сразу меняйте все дефолтные пароли** после первого запуска.
- На логин возвращается `securityWarning`, если вход выполнен под дефолтным аккаунтом.
- По возможности включите **2FA** и отключите самостоятельную регистрацию (`allow_registration`).

Технические меры:
- Пароли — `pbkdf2Sync` (120 000 итераций)
- Сессии на криптографических токенах (HttpOnly + SameSite=Strict), хранятся в БД
- Все чувствительные эндпоинты требуют авторизации + проверки роли
- Защита регистрации: капча + honeypot + тайминг + rate limiting + серверная верификация
- Загрузка файлов: санитизация имён, лимит **25 МБ на файл, до 6 файлов за раз**, авто-сжатие изображений на клиенте

**Предупреждение:** не выставляйте проект напрямую в интернет без reverse proxy + HTTPS + аудита.

## 📡 API (основные эндпоинты)

### Публичные
- `POST /api/auth/login`, `POST /api/auth/register`, `GET /api/auth/check-username`
- `GET /api/public/articles`, `GET /api/public/settings`
- `GET /api/public/tool?id=…` — данные публичной карточки инструмента (без авторизации)

### Личный кабинет
- `GET /api/cabinet/me`, `PUT /api/cabinet/profile`, `POST /api/auth/logout`
- `GET /api/cabinet/my-card`, `GET /api/cabinet/my-tools`, `POST /api/cabinet/tool-photo`
- `POST /api/cabinet/2fa/*` — настройка/подтверждение/отключение 2FA
- `POST /api/support/send`, `GET /api/support/messages`, `POST /api/support/read`
- `GET /api/request-types`, `GET /api/requests/mine`, `POST /api/requests`
- `POST /api/worklogs`, `GET /api/worklogs/mine`, `DELETE /api/worklogs?id=…` — учёт своего времени

### Админ-панель
- `GET /api/dashboard/stats`
- `GET/POST/PUT/DELETE /api/crud/articles`
- `GET/POST/PUT/DELETE /api/media`, `GET /api/category-icons`, `GET /api/standard-avatars`
- `GET/POST/PUT/DELETE /api/crud/employees`
- `GET/POST/PUT/DELETE /api/crud/tools`, `/api/crud/tool-categories`
- `POST /api/tools/issue|return|transfer`, `GET /api/tools/history|details`
- `GET /api/tools/qr?id=…`, `POST /api/tools/photo`, `POST /api/tools/set-avatar`
- `GET /api/requests`, `POST /api/requests/approve?id=…`, `POST /api/requests/reject?id=…`
- `GET /api/requests/vacations` — сводка отпусков (одобренные + ожидающие)
- `GET /api/worklogs/summary`, `GET /api/worklogs/all?user_id=…` — учёт времени по всем
- `GET /api/support/tickets`, `GET /api/support/users`, `POST /api/support/reply`, `POST /api/support/create`
- `GET/POST /api/settings`
- `GET/POST/PUT/DELETE /api/users` (только Superadmin)
- `GET/DELETE /api/logs`, backup-эндпоинты

Полный список — в `server.js` и `src/routes/`.

## 🛠️ Разработка

- Нативный **`node --watch`** (Node 18.11+ / 20+), без сборки и бандлеров
- Весь фронтенд — Vanilla JS + `fetch`
- Тесты: `npm test` (встроенный `node:test`)

**Полезные советы:**
- Инициализация фронтенда — внутри `DOMContentLoaded`.
- Любой API-обработчик обязан завершать ответ через `res.end()` / `sendJson(...)`.
- Новые эндпоинты добавляйте до блока раздачи статики.

## ❓ Troubleshooting

- **Порт 3080 занят** — задайте `PORT` в `.env` (или измените в `server.js`).
- **Не работает загрузка файлов** — папка `uploads/` создаётся автоматически; проверьте права.
- **Фото не грузится** — большие изображения сжимаются в браузере; если файл всё равно больше 25 МБ, будет понятная ошибка с именем и размером.
- **Старый QR ведёт на вход** — перегенерируйте наклейку (кнопка «Печать/Сохранить QR» в карточке): новые QR ведут на публичную страницу `/tool.html`.
- **Сессии сбрасываются** — нормально при `npm run dev` (перезапуск). В продакшене — `npm start`.
- **Сбросить демо-данные** — остановите сервер, удалите `db.sqlite`, запустите снова.

## ⚠️ Ограничения (Beta)

- Пагинация не везде (часть списков грузится целиком).
- Rate limiting — в памяти (сбрасывается при перезапуске).
- Фронтенд админки (`public/app.js`) — один большой файл.
- SQLite — не для высоконагруженных проектов.
- HTTPS не встроен (ставьте за reverse proxy).
- UI/API могут меняться между версиями. Делайте бэкапы `db.sqlite` и `uploads/`.

## 🚢 Production / Деплой

- Запуск через `npm start` (без `--watch`).
- Reverse proxy (Nginx/Caddy) + HTTPS.
- Регулярные бэкапы `db.sqlite` и `uploads/`.
- Постоянная работа — PM2 / systemd / Docker.
- Сменить дефолтные пароли, включить 2FA, рассмотреть отключение регистрации.

```bash
pm2 start server.js --name admin-panel
```
